# 数据接入管理与保留策略

## 功能归属

数据管理统一为四个一级入口：

| 入口 | 使用场景 |
| --- | --- |
| 数据集 | 为设计器提供可绑定的数据及字段 |
| 数据源 | 配置数据库、HTTP 接口与原生 WebSocket 来源 |
| 推送接入 | 接入方配置、接收台账、失败消息（死信）三个二级页面 |
| 接入运维 | 跨来源的告警、访问审计、实时连接和公共保留策略 |

接收台账和失败消息仅属于第三方主动推送，HTTP 取数失败不会进入死信。原生 WebSocket 的连接故障通过运维告警和连接状态查看。WebSocket 数据集若采用 SQL/API 桥接，其底层数据仍遵循相应数据库或 HTTP 来源的规则。

旧链接 `?tab=batches`、`?tab=dead` 仍能进入对应页面，规范化为 `?tab=inbound&inboundTab=batches` 或 `inboundTab=dead`。原有按钮权限保留；只有台账或死信查看权限的人员可进入相应二级页面，不会因此获得接入方列表、编辑或密钥权限。

## 按保留对象配置

### 业务数据

- 推送接入：在“接入方配置 → 编辑 → 业务数据保留”设置标准业务记录期限。0 为长期，正数按平台更新时间到期清理；去重摘要和失败消息继续按推送规则保护。
- HTTP：调用接口不自动建立业务历史表。
- 原生 WebSocket：消息仅在当前应用实例内存中暂存，当前消息覆盖更新，无人读取约 120 秒回收连接，重启后不恢复消息。
- 数据库来源：历史保留由所连接的数据库管理，平台查询不自动复制或清理其业务记录。

### 临时缓存

入口：数据源 → 选择 HTTP 来源 → 接口 → 新增或编辑 → 临时缓存。

| 配置 | 含义 |
| --- | --- |
| 缓存最新响应 | 开启时按接口与查询参数保存最新一份加密响应；关闭后不读写响应快照 |
| 缓存有效秒数 | 0–3600，默认共享 1 秒；多个页面可复用同一查询结果 |
| 故障沿用缓存秒数 | 0–86400，默认 0；大于 0 时来源暂时故障可返回标记为过期的缓存 |

可视控件与高级 JSON 双向同步，保留其他手写策略。关闭会同时设置 `cacheSeconds`、`sharedFetchSeconds`、`staleIfErrorSeconds` 为 0；调整有效期时合并旧缓存参数，避免残留的旧值扩大窗口。旧快照按接收时登记的到期时间分批删除，关闭不立即清空旧快照。媒体接口另有临时文件及引用保留规则。

### 日志、原文和处理明细

推送原始报文和成功处理明细仍在接入方中单独配置，详见本页“按保留对象配置”中的推送保留规则。它们与业务记录是独立副本。

公共入口：接入运维 → 保留策略。

| 配置 | 默认 | 清理范围 |
| --- | --- | --- |
| 访问审计保留天数 | 30；没有保存公共配置时沿用部署环境原值 | HTTP、推送、媒体、WebSocket 生命周期及保留期审计，按创建时间 |
| 已确认告警保留天数 | 30 | 仅已确认告警，按最近发生时间；未确认告警继续保留 |
| 测试日志保留天数 | 30 | 系统操作日志中的数据集测试和 HTTP 接口测试，按操作时间；不清理其他模块日志 |

三项均接受 1–3650 的整数。修改会作用于已有日志；公共策略不受上方来源筛选影响。保存需要独立权限 `dashboard:integration:policy`，查看沿用 `dashboard:integration:monitor`。迁移只给管理员角色增加配置权限，不自动扩大普通角色权限。

新数据集测试、HTTP 接口测试均关闭系统操作日志的请求及返回正文保存，保留操作人、地址、时间、执行结果和耗时等元数据。该规则固定生效，没有允许重新开启敏感正文日志的开关。历史测试日志中已有的正文不立即擦除，随测试日志保留期清理。

公共维护沿用接入维护任务，默认每 30 秒执行，每类最多 1000 条；到期后分批清理。推送业务和处理明细另用默认每 300 秒的限量维护，不混用缓存有效期。

## 统一运维

方式筛选包含 HTTP 主动取数、推送接收、原生 WebSocket、媒体访问和推送保留期清理。选择来源时同时保留其方式，避免同名来源和接入方混淆。审计、告警和指标共用筛选；旧的 HTTP 告警 `source:endpoint` 和新的审计 `source/endpoint` 均按来源精确归属，不以模糊子串匹配。

请求概况只统计 HTTP、推送、媒体请求；正常 WebSocket 生命周期及保留期清理不会计入请求失败。推送待处理、死信、标准业务记录独立显示。

实时连接页面提供当前应用实例的连接状态、最近消息时间、重连次数、消息数、接收字节数，以及事件丢弃/持久化失败计数。只对连接生命周期和故障写审计，不逐条记录消息；不向运维页返回上游地址、订阅内容、凭证或消息正文。连接空闲回收后不再出现在当前连接列表，可查生命周期审计。多实例部署时本页明确只代表所访问实例，尚不是跨节点聚合看板。

历史媒体审计若仍能关联媒体引用，会补充来源归属；引用已清理且仅剩摘要的历史记录不凭空推断来源，只能在全部来源下查看。

## 迁移与验证

现有环境先备份，再执行：

1. `dashboard_integration_monitoring.sql`：告警分类、审计来源归属与查询索引。旧、新告警键同时存在时保留各自历史和计数，不强行覆盖。
2. `dashboard_integration_policy.sql`：公共策略表和独立配置权限。
3. 更新后端和前端。

新环境初始化脚本已串联两项迁移。不要为本次更新重新导入本地业务数据或全量菜单初始化。没有保存公共策略时使用默认值，推送接入原有业务期限不变。

隔离联调复用 `scripts/test-dashboard-retention.sh`：

```bash
# 将 websockets==15.0.1 安装到单独测试虚拟环境，供回环模拟上游使用。
INTEGRATION_UNIFICATION_TEST=1 RETENTION_KEEP_RUNNING=1 \
INTEGRATION_TEST_PYTHON=/绝对路径/测试虚拟环境/bin/python \
scripts/test-dashboard-retention.sh
```

脚本新建临时 MySQL 库、独立 Redis 和仅监听回环地址的 HTTP/WebSocket 模拟服务，不复制真实用户、业务或密钥。覆盖公共策略权限、严格校验、HTTP 缓存、测试日志正文关闭、WebSocket 消息与重连、运维范围筛选和清理边界。只有该隔离场景临时开启本机目标测试开关；结束脚本自动清理临时服务及数据库。
