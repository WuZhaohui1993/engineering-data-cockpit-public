# 本地运行、测试与验收

本文列出当前脚本的使用方式和验收要求。已有验证结果与未完成项见[测试与已知限制](测试与已知限制.md)；界面操作见[用户说明书](examples/README.md)。本地样例只验证平台能力，不代表现场数据已接通。

## 本地配置与启动

准备 JDK 17+、Maven、Node.js、pnpm、MySQL 和 Redis。维护脚本使用 `import.meta.dirname`，建议使用 Node.js 22+。依赖版本以 `ruoyi-backend/pom.xml` 和 `ruoyi-ui/package.json` 为准。

在项目根目录首次创建配置，已有文件不要覆盖：

```bash
cp -n config/ruoyi-local.env.example config/ruoyi-local.env
```

填写被 Git 忽略的本地配置文件；不要输出其中的凭证。主要配置如下：

| 配置 | 用途 |
| --- | --- |
| `MYSQL_*`、`REDIS_*` | 平台数据库与缓存；默认本机 3306/6379 |
| `BACKEND_PORT`、`FRONTEND_PORT` | 默认后端 8080、前端 5173 |
| `FRONTEND_HOST` | 前端监听地址，默认 `127.0.0.1`；局域网访问设为 `0.0.0.0` |
| `TOKEN_SECRET` | 令牌密钥；本地未设置时脚本生成并保存在 `.local/ruoyi/token-secret` |
| `DASHBOARD_DATASOURCE_ENCRYPTION_KEY` | 登记数据源凭证时所需的固定加密密钥；启动脚本不会生成，须通过环境或被忽略的配置注入，并随凭证备份安全保管 |
| `LABOR_MYSQL_*`、`LABOR_API_BASE_URL`、`LABOR_API_TOKEN`、`LABOR_PROJECT_CODE` | 外部来源连接，只在获授权后填写最小只读配置 |
| `DASHBOARD_API_ALLOWED_HOSTS` | API/远程 JSON 主机白名单 |
| `DASHBOARD_WEBSOCKET_ALLOWED_ORIGIN`、`DASHBOARD_WEBSOCKET_ALLOWED_HOSTS` | 平台 WebSocket 来源与上游主机白名单；后者可额外加入本地环境文件 |

首次准备专用本地测试库时才执行：

```bash
./scripts/init-local-mysql.sh
```

该脚本会创建库、按需导入 RuoYi 基础表，并每次执行 `dashboard.sql` 和品牌清理 SQL，包含菜单及示例数据写入。它不是只读检查，也不能保证修复已有主键冲突或缺失的示例页；不得对生产或共享库直接运行。使用已有快照时改按[数据库快照与恢复](../database/backups/README.md)操作，初始化和恢复是不同流程。

先检查 8080/5173 是否已有本项目实例；只有缺少实例时才启动。前后端脚本均前台运行，可在两个终端分别执行：

```bash
./scripts/start-backend.sh
```

```bash
./scripts/start-frontend.sh
```

后端脚本仅在 JAR 不存在时自动构建，修改后端后须先重新打包；运行时使用 `.local/ruoyi/runtime/` 中的副本，重新构建不会自动更新运行中的服务。前端脚本使用 pnpm，缺少 `node_modules` 时会安装依赖，代理默认指向本地后端。

浏览器访问 `http://127.0.0.1:5173`，后端就绪检查为 `GET http://127.0.0.1:8080/captchaImage`。关闭实例优先在所属终端按 Ctrl+C；保留共享的 MySQL/Redis，不批量结束 Java、Node 或数据库进程。

局域网其他电脑访问时，在 `config/ruoyi-local.env` 中设置 `FRONTEND_HOST=0.0.0.0`，重启前端后访问 `http://运行系统的电脑局域网IP:5173/index`。也可单次运行 `FRONTEND_HOST=0.0.0.0 ./scripts/start-frontend.sh`；命令行环境变量优先于本地配置。`0.0.0.0` 是监听地址，不能作为浏览器访问地址。前端的 `/dev-api` 继续通过 Vite 代理到本机后端，无需将代理目标改为访问者的电脑地址。

使用 WebSocket 实时组件时，还须在 `DASHBOARD_WEBSOCKET_ALLOWED_ORIGIN` 的逗号分隔列表中加入实际网页来源（例如 `http://192.168.6.223:5173`），保留原有本机来源并重启后端。IP 或端口变化后同步更新该列表，不使用 `*`。

## 自动验证入口

以下命令均从项目根目录执行：

```bash
node --test ruoyi-ui/tests/*.test.mjs
npm --prefix ruoyi-ui run build:prod
mvn -f ruoyi-backend/pom.xml test
mvn -f ruoyi-backend/pom.xml -DskipTests package
git diff --check
```

Node 测试覆盖组件配置、生产渲染函数和部分源码约束；构建、单元测试和真实浏览器验收分别记录，不能互相替代。`-DskipTests package` 只表示打包，不表示测试通过。

全栈接口冒烟使用：

```bash
./scripts/test-local-stack.sh
# 仅在构建产物与当前代码一致时跳过构建
SKIP_BUILD=1 ./scripts/test-local-stack.sh
```

除上述开发依赖外，脚本还需要 `curl`、`jq`、`mysql`、`redis-cli` 和 `lsof`。账号通过 `TEST_ADMIN_USERNAME`、`TEST_ADMIN_PASSWORD` 注入。默认测试端口为 18080/15173、Redis 库为 15，可用 `TEST_BACKEND_PORT`、`TEST_FRONTEND_PORT`、`TEST_REDIS_DATABASE` 覆盖。

**测试端口隔离不等于数据库隔离。** 脚本仍连接 `config/ruoyi-local.env` 指定的 MySQL，会执行初始化 SQL、临时关闭验证码、增删测试对象，退出时尝试清理和恢复；只在专用本地测试库使用。日志位于 `.local/ruoyi-e2e-backend.log`、`.local/ruoyi-e2e-frontend.log`，自动构建日志为 `.local/ruoyi-maven.log`、`.local/ruoyi-frontend-build.log`。

第三方接入专项回归使用：

```bash
./scripts/test-dashboard-integration.sh
# 仅在 ruoyi-admin JAR 与当前代码一致时跳过打包
SKIP_BUILD=1 ./scripts/test-dashboard-integration.sh
```

专项脚本默认使用后端 `18080`、模拟第三方 `18081` 和 Redis 15 库，不启动前端。它会临时开启仅对该隔离进程生效的本机 HTTP/回环目标开发开关，验证动态 HMAC、endpoint/数据集生命周期、媒体和入站幂等链路；退出时按 `mvp-*` 前缀清理数据并恢复验证码。日志为 `.local/integration-mvp-backend.log` 和 `.local/integration-mvp-package.log`。开发开关不能复制到生产配置。

现有全栈报告在第 6 步因缺少业务来源示例页中止，未通过全套冒烟。脚本仍要求该页面具有 6 个组件；执行前应核对测试库样例，不能靠重复初始化或改动业务页面来凑齐断言。

组件样例的加载、绑定和清理见[大屏组件测试数据](大屏组件测试数据.md)。

## 浏览器与现场验收

| 范围 | 必须核对 |
| --- | --- |
| 管理外壳 | 登录/退出、角色按钮与菜单、侧栏高亮；明暗主题、主题色、较大/默认/稍小布局；侧栏和顶部/混合导航下无溢出、无控制台错误 |
| 设计器 | 拖动缩放、图层/分组/锁定、字段映射、过滤器、选项卡；草稿保存重开、预览、发布后布局与数据一致；单个组件失败不白屏 |
| 运行与全屏 | 完整显示/等比铺满/拉伸铺满；页面编码跳转、前进后退、退出全屏；切页期间原生全屏节点保持连接且身份不变 |
| 菜单与权限 | 菜单配置取消不写入、确认只提交一次；目录移动后路径/参数/高亮正确；真实 `sys_menu`、`sys_role_menu` 与后端权限一致，新菜单不自动扩大普通角色授权 |
| 版本与分享 | 运行使用发布版本、历史预览与草稿互不混淆、回滚形成新版本；匿名分享仅访问令牌绑定的页面/版本/组件数据，过期、撤销及集合外页面均被拒绝 |
| 数据与资源 | JSON 修改后按刷新策略生效，数据集和字段可追溯；图片/视频/地图资源有效；失败、空数据与未接入不显示为 0 |

四类数据集分别准备最小可执行样本，状态和接口字段以[数据集与数据源设计](数据集与数据源设计.md)为准：

| 类型 | 最小样本与失败场景 |
| --- | --- |
| SQL | 只读参数查询；绑定变量、行数/超时上限、无数据及写操作/注入拒绝 |
| API | 登记接口；主机白名单、服务端鉴权、响应映射、超时与来源失败 |
| JSON | 静态数组和受控远程 JSON；大小限制、字段声明及非法内容拒绝 |
| WebSocket | 平台握手/订阅、断连与质量状态；轮询桥接和受控原生上游分别记录，不能相互替代 |

历史生成菜单的冗余超级管理员授权可用 `scripts/repair-dashboard-generated-menu-role.sh` 专项修复。执行前核对严格匹配的生成菜单范围；脚本仅允许本地库，备份至 `.local/menu-repair/`，只删除匹配的 `role_id=1` 关联并验证普通角色授权不变。它不是通用权限清理工具。

安全限制和待验证项见[安全与许可证](安全与许可证.md)。接入真实来源前，确认接口或表、字段/字典、业务时间、权限、脱敏规则和来源负责人。以最小只读数据集回放成功、无数据、鉴权失败、权限不足、超时、字段缺失和来源停用，并用页面版本、数据集编码、请求 ID 关联证据。外部现场响应、数据权限、原生 WebSocket 和长周期稳定性未取得证据时，保留“待验证”。

部署验收另需验证实际反向代理与 WebSocket 链路、资源持久化、备份恢复、发布回滚、分享撤销、跨用户越权拒绝，以及约定并发下的延迟、连接数和消息速率。保存日期、代码版本、环境、测试人、样本摘要、结果、截图/日志位置与未闭环事项；凭证、令牌和人员敏感数据不进入报告。

两种外部接入的业务验收矩阵和待确认项见[第三方数据接入需求](第三方数据接入需求.md)。新 endpoint 执行器已支持动态 HMAC、业务成功标识、JSON/表单请求和受控二进制媒体；入站接收、幂等台账和死信链路也已实现。专项回归包含两个后端、共享快照、真实故障死信、重放、下游页面、告警和实例中断恢复；不能代替第三方真实网络/凭证/字段、扫描服务和生产容量验收。具体来源边界应在目标环境的独立适配评审中记录。
