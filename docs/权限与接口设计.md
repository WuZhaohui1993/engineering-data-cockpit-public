# 权限与接口设计

接口以当前 `DashboardController`、WebSocket 拦截器、前端路由和 `dashboard.sql` 为准。REST 首选前缀 `/dashboard`，兼容 `/api/dashboard`；下表省略此前缀。分页返回 `TableDataInfo`，其他 JSON 接口使用 RuoYi `AjaxResult`。

## 授权边界

管理接口使用 RuoYi 角色/菜单/按钮权限。设计器动态路由使用 `dashboard:page:edit`，登录运行路由使用 `dashboard:page:view` 或 `dashboard:page:list`，分享路由无需登录。以下表格将权限简写为 `page:list` 等，实际均需加 `dashboard:`。

当前 `DashboardService` 和 Mapper 查询没有页面 ACL 或项目/部门 `DataScope` 过滤；具备相应功能权限的用户并不会自动按页面创建者、部门或项目隔离。数据集参数只限制格式与声明，不能充当数据授权。匿名分享使用独立令牌边界，不继承创建者的动态角色/行级数据范围。

## 页面与版本

| 方法 | 路径 | 权限 |
| --- | --- | --- |
| GET | `/page/list`、`/page/folders`、`/page/recycle`、`/page/{pageId}` | `page:list` |
| GET | `/page/published` | `page:view` 或 `page:list` |
| POST | `/page`、`/page/{pageId}/copy`、`/page/folder` | `page:add` |
| PUT | `/page`、`/page/{pageId}/draft`、`/page/folder` | `page:edit` |
| DELETE | `/page/{pageId}`、`/page/folder/{folderId}` | `page:delete` |
| POST | `/page/{pageId}/restore` | `page:restore` |
| DELETE | `/page/{pageId}/purge`、`/page/recycle` | `page:purge` |
| GET | `/page/{pageId}/preview`、`/page/code/{pageCode}/preview`、`/page/{pageId}/revision/{revisionId}/preview` | `page:preview` |
| GET | `/page/{pageId}/runtime`、`/page/code/{pageCode}/runtime` | `page:view` 或 `page:list` |
| POST | `/page/{pageId}/publish` | `page:publish` |
| POST | `/page/{pageId}/rollback/{revisionId}` | `page:rollback` |
| POST | `/page/{pageId}/menu` | `page:menu` |
| GET / POST | `/page/{pageId}/shares` | 分别为 `share:list` / `share:create` |
| PUT | `/page/{pageId}/shares/{shareId}`（仅更改版本模式） | `share:create` |
| DELETE | `/page/{pageId}/shares/{shareId}` | `share:revoke` |

更新页面用请求体 `pageId`；保存草稿提交 `schemaJson`，发布备注用 `publishNote`，回滚备注用 `note`。菜单登记、版本及分享参数见[页面版本与分享](页面版本与分享.md)。

## 数据集、数据源与资源

数据源和数据集使用同一组 `dataset:*` 权限，没有独立的 `source:*` 权限。

| 方法 | 路径 | 权限 |
| --- | --- | --- |
| GET | `/dataset/list`、`/dataset/{datasetId}`、`/dataset/group/list`、`/source/list`、`/source/{sourceCode}` | `dataset:list` |
| POST / PUT | `/dataset`、`/dataset/group`、`/source` | `dataset:edit` |
| DELETE | `/dataset/{datasetId}`、`/dataset/group/{groupId}`、`/source/{dataSourceId}` | `dataset:edit` |
| POST | `/dataset/{datasetId}/test`、`/source/{sourceCode}/test` | `dataset:test` |
| POST | `/dataset/{datasetCode}/preview`、`/dataset/{datasetCode}/preview-widget` | `page:preview` 或 `dataset:test` |
| GET | `/asset/list`、`/map/list`、`/asset/page`、`/map/page`、`/map/{mapId}`、`/resource/folders` | `resource:list` |
| POST / PUT | `/asset`、`/map` | `resource:edit` |
| DELETE | `/asset/{assetId}`、`/map/{mapId}` | `resource:delete` |
| POST / PUT | `/resource/folder` | `resource:folder` |
| DELETE | `/resource/folder/{folderId}` | `resource:folder` |

更新数据集/数据源使用请求体 `datasetId/dataSourceId`，不是 `PUT /dataset/{id}` 或 `PUT /source/{id}`。字段通过数据集详情或测试结果获取，没有独立 `/dataset/{code}/fields` 接口。数据集测试会保存测试结果并补齐新字段；预览组件请求体为 `{params, filters}`，普通数据集测试/预览直接提交参数对象。

资源管理使用 `/asset/page`、`/map/page`，接收 `pageNum/pageSize`（默认 1/10，每页最多 1000 条）、`keyword/folderId`，图库还支持 `assetType`；返回 `rows/total`。地图先合并内置地图再统一筛选、计数和分页。原 `/asset/list`、`/map/list` 保留完整目录供设计器选择资源。

JSON 数据统一在数据集管理中维护，保存为 `dashboard_dataset` 的 `JSON` 类型；资源管理只维护图库、视频和地图边界，移除原重复 JSON 入口不会删除数据集或改变 `datasetCode` 绑定。

## 运行与公开接口

| 方法 | 路径 | 授权 |
| --- | --- | --- |
| POST | `/runtime/data` | `page:view`、`page:list`、`dataset:test` 任一 |
| POST | `/runtime/preview/data` | `page:preview` |
| GET | `/public/share/{token}` | 有效分享令牌，读取入口页 |
| GET | `/public/share/{token}/page/{pageCode}` | 有效分享令牌及集合成员 |
| GET | `/public/share/{token}/version`、`/public/share/{token}/page/{pageCode}/version` | 与分享配置相同的令牌、成员、页面状态及版本校验；仅返回版本元数据 |
| POST | `/public/share/{token}/runtime/data` | 有效分享令牌及入口页绑定 |
| POST | `/public/share/{token}/page/{pageCode}/runtime/data` | 有效分享令牌及成员页绑定 |
| POST | `/runtime/media/ref` | 登录权限及页面/版本/组件/数据集绑定 |
| GET | `/runtime/media/{mediaRef}` | 登录权限及媒体引用绑定 |
| POST / GET | `/public/share/{token}[/page/{pageCode}]/media/ref`、`media/{mediaRef}` | 有效分享令牌、成员页面、版本及媒体引用绑定 |
| GET | `/assets/map/{mapCode}.json` | 公开的受控 GeoJSON 资源 |

媒体代理先把数据集返回的一次性候选换成绑定页面/版本或分享的最终 `mediaRef`，再从独立路径读取。服务端逐次复核会话或分享令牌、页面/版本绑定和引用状态；浏览器不能提交任意上游 URL、路径或凭证。媒体不使用 `/open-api` 匿名边界。

登录运行请求为 `{pageId, widgetId, datasetCode, params, filters}`；历史预览可附加 `revisionId`，正式运行仍按当前发布版本执行。分享按页面编码取数时可省略 `pageId`，服务端从成员记录解析。请求不能提供页面 JSON 或上游连接配置来替换服务端绑定。

服务端先读取页面，并按分享模式解析当前发布或固定版本，再检查 `widgetId` 与 `datasetCode` 是否绑定，正式运行要求数据集启用；错误可表现为组件级 `quality` 或标准业务错误，不能一概依赖 HTTP 403 判断。结果字段见[数据集与数据源设计](数据集与数据源设计.md)。

## WebSocket

登录入口为 `/dashboard/runtime/ws`，分享入口为 `/dashboard/runtime/share/ws`，均兼容 `/api/dashboard` 前缀。`SecurityConfig` 仅放行公开分享 REST、分享 WebSocket 和受控地图资源；管理接口仍受登录保护。

握手查询带 `token`、`widgetId`、`datasetCode`；登录场景必须带 `pageId`，分享场景必须带成员 `pageId` 或 `pageCode` 至少一个。预览使用 `preview=1`，历史预览可带 `revisionId`。登录握手要求 `page:view/page:list`，预览要求 `page:preview`；分享握手验证令牌及页面。每次推送重新校验页面版本、组件绑定和数据集状态。

客户端消息仅为 `{type: "subscribe" | "refresh", params: {}, filters: []}`，不能改变连接固定的数据集或提交上游 URL。每连接对应一个组件，不是任意多数据集订阅总线。连接数、消息频率和上游读取限制见[数据集与数据源设计](数据集与数据源设计.md)。

## 外部系统集成接口

管理端前缀为 `/dashboard/integration`，使用 `dashboard:integration:*` 权限：

- `GET/POST/PUT/DELETE /dashboard/integration...` 管理接入方、状态和密钥；
- `/dashboard/integration/endpoints/{sourceCode}` 管理、测试出站 endpoint；
- `/dashboard/integration/batches`、`batch/{batchId}` 查询接收台账；
- `/dashboard/integration/dead-letters` 和 `dead-letters/{messageId}/replay` 查询、重放死信。

第三方调用使用独立开放接口，不授予后台用户权限：

| 方法 | 路径 | 授权 |
| --- | --- | --- |
| POST | `/open-api/v1/integrations/{integrationCode}/events` | 接入方状态、endpoint、IP/Origin、限流及登记 provider |
| POST | `/open-api/v1/integrations/{integrationCode}/{endpointCode}` | 同上，endpointCode 必须与接入方登记一致 |
| GET | `/open-api/v1/integrations/{integrationCode}/messages/{messageId}` | 同一接入方认证和范围 |
| GET | `/open-api/v1/integrations/{integrationCode}/requests/{platformRequestId}` | 同一接入方认证和范围 |

`SecurityConfig` 只跳过这些路径的后台 JWT，真正的 API Key/Bearer/HMAC、时间窗、nonce、IP、幂等和项目范围由接入服务校验。路径中的 `integrationCode` 是入站身份，不等同于出站 `sourceCode`。`/runtime/data` 与 `/runtime/ws` 仍只是页面读取入口。

管理权限实际为 `integration:list/view/add/edit/delete/test/key/pause/revoke/deadletter/replay` 加 `dashboard:` 前缀。菜单脚本只自动授权管理员角色；其他角色必须按职责显式授权，Controller 注解、菜单按钮和前端计算保持一致。

## 菜单配置中的现有差异

- `dashboard.sql` 提供 `page:recycle/page:folder` 按钮，但回收站读取 REST 实际要求 `page:list`，页面文件夹写操作分别要求 `page:add/edit/delete`；角色授权需同时满足界面入口和接口权限。
- 登录运行支持 `page:view`，基础菜单 SQL 未单独插入该按钮；自动登记运行菜单以该权限保存，现有 `page:list` 也可运行。不要把仅查看角色视为已由初始化脚本完整配置。
- 页面、数据集和资源管理菜单通过 `sys_menu` 维护；设计器及参数化运行页通过前端 `dynamicRoutes` 管理，`meta.activeMenu` 回指 `/dashboard/page`。

当前“数据管理”使用单一菜单，原数据集列表/编辑/测试权限归入同一父菜单，形成 1 个菜单和 16 个按钮权限；导航、数据集、入站与运维的权限字符串保持独立。原来源操作权限保持，普通数据集角色只补导航资格。新环境仍需在执行迁移后核对真实 `sys_menu/sys_role_menu`、侧栏、按钮和接口拒绝行为。

敏感来源、接口和密钥配置使用独立权限控制，响应禁止缓存，审计日志不保存请求或响应正文。公开文档不记录凭证字段、真实地址或密钥回显接口；部署时以对应 Controller 和环境配置为准。
