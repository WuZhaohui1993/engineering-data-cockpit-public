# 测试与已知限制

本文说明可重复的验证入口和当前边界。测试结果只代表执行它们的代码、数据库和浏览器环境，不能替代目标环境验收。

## 自动检查

从仓库根目录执行：

```bash
node --test ruoyi-ui/tests/*.test.mjs
npm --prefix ruoyi-ui run build:prod
mvn -f ruoyi-backend/pom.xml test
mvn -f ruoyi-backend/pom.xml -DskipTests package
git diff --check
```

需要完整本地链路时，再执行：

```bash
./scripts/test-local-stack.sh
./scripts/test-dashboard-integration.sh
```

专项脚本会连接配置文件指定的本地 MySQL/Redis，并创建临时测试对象；只在专用测试环境运行。脚本输出和浏览器截图存放在被忽略的 `.local/`，不应提交到仓库。

## 建议的浏览器回归

登录后至少检查：

- 管理页的菜单、按钮权限、侧栏高亮、明暗主题和三档全局尺寸；
- 设计器的拖动、缩放、图层、分组、锁定、字段映射、草稿保存、预览和发布；
- 运行页的页面跳转、全屏、刷新、空数据、错误数据和单组件失败隔离；
- 版本与分享的发布版本读取、回滚、过期、撤销及集合外页面拒绝；
- SQL、HTTP、JSON、WebSocket 四类数据源的成功、空结果、超时、鉴权失败、字段缺失和超限；
- 图片、视频、GeoJSON、富文本、受控表单和沙箱内容的资源校验与权限边界。

## 已知限制

- 页面和数据集目前没有项目/部门级行级 ACL。前端筛选和隐藏按钮不能代替来源层数据权限。
- 数据源凭证依赖部署环境注入和密钥管理；仓库只提供示例配置，不包含可用凭证。
- 公网部署仍需单独配置 HTTPS、反向代理、WebSocket Origin、备份恢复、漏洞扫描和容量监控。
- 原生 WebSocket 状态是应用实例级的；多实例聚合、跨节点断路和长周期稳定性需要目标环境验证。
- 分享链接本身是访问凭证。反向代理日志和浏览器历史记录应避免保存完整分享路径或 WebSocket 查询令牌。
- 静态测试和构建不能证明浏览器视觉、真实第三方网络、生产数据质量或容量指标通过。

发现新的限制时，记录复现步骤、环境、影响范围和临时规避方式；不要把一次性部署或项目验收快照写入公共文档。
